# دليل دورة إيجار العقارات — Rental Workflow

## 1. الدورة الرئيسية

```text
Property Draft
→ Make Available
→ Create Rental Contract
→ Activate Contract
→ Reserved (للعقد المستقبلي) / Rented (للعقد الجاري)
→ Invoicing and Maintenance
→ Renewal / Expiry / Close / Cancel
→ Available عند عدم وجود عقد حالي أو مستقبلي
```

## 2. حالات العقار

| الحالة التقنية | الاسم الظاهر | الاستخدام |
|---|---|---|
| `draft` | Draft / مسودة | العقار تحت الإعداد ولا يمكن تأجيره بعد |
| `available` | Available / متاح | العقار جاهز لإنشاء عقد إيجار |
| `booked` | Reserved / محجوز | يوجد عقد ساري تقنيًا لكنه يبدأ في تاريخ مستقبلي |
| `on_lease` | Rented / مؤجر | يوجد عقد إيجار جارٍ يغطي تاريخ اليوم |
| `sale` | For Sale / معروض للبيع | العقار داخل دورة البيع |
| `sold` | Sold / مباع | تم بيع العقار |

### أزرار العقار

#### Draft

- **Make Available**: يجعل العقار متاحًا بعد استكمال بياناته.

#### Available — عقار للإيجار

- **Create Rental Contract**: يفتح معالج إنشاء العقد ويملأ العقار والشركة تلقائيًا.

#### Reserved أو Rented

- **View Active Contract**: يفتح العقد المرتبط.

#### Rented

- **Maintenance Requests**
- **View Invoices**
- **View Documents**

### المزامنة التلقائية

لا يتم الاعتماد على تغيير حالة العقار يدويًا أثناء دورة الإيجار. النظام يفحص جميع العقود السارية الخاصة بالعقار:

1. وجود عقد يغطي تاريخ اليوم ⇒ `on_lease`.
2. عدم وجود عقد حالي مع وجود عقد مستقبلي ⇒ `booked`.
3. عدم وجود عقد حالي أو مستقبلي ⇒ `available`.

وجود عقد حالي له أولوية على عقد تجديد مستقبلي، ولذلك يظل العقار ظاهرًا كمؤجر حتى نهاية العقد الحالي.

## 3. حالات عقد الإيجار

| الحالة التقنية | الاسم الظاهر | المعنى |
|---|---|---|
| `new_contract` | Draft / مسودة | عقد تحت الإعداد ولم يبدأ تشغيله |
| `running_contract` | Active / ساري | عقد مفعّل ويقوم بحجز العقار |
| `expire_contract` | Expired / منتهي | انتهى تاريخ العقد |
| `close_contract` | Closed / مغلق | تم إغلاق العقد إداريًا مع الاحتفاظ بالتاريخ المالي |
| `cancel_contract` | Cancelled / ملغي | تم إلغاء العقد بسبب مسجل |

## 4. إنشاء عقد جديد

يمكن إنشاء العقد بطريقتين:

### من العقار

1. افتح عقارًا حالته **Available**.
2. اضغط **Create Rental Contract**.
3. سيتم تمرير العقار والشركة إلى المعالج تلقائيًا.
4. أدخل المستأجر والمدة وتاريخ البداية وسياسة الدفع وباقي الإعدادات.
5. ينشأ عقد واحد فقط.

### من قائمة العقود

1. افتح **Rental Contracts**.
2. اضغط **New**.
3. حقل العقار يعرض العقارات المتاحة داخل الشركة الحالية فقط.
4. استكمل بيانات العقد ثم احفظه كمسودة.

## 5. الحقول اللازمة قبل التفعيل

لا يمكن تفعيل العقد بدون:

- Property — العقار.
- Tenant — المستأجر.
- Company — الشركة.
- Start Date — تاريخ البداية.
- Duration — المدة.
- End Date — تاريخ النهاية المحسوب.
- Rent Amount — قيمة الإيجار.
- Payment Term — دورية الدفع.
- Invoice Start Date — بداية الفوترة.
- Installment Product — منتج قسط الإيجار.

ويتحقق النظام أيضًا من:

- صحة ترتيب التواريخ.
- أن بداية الفوترة داخل فترة العقد.
- أن القيمة والمدة أكبر من صفر.
- تطابق شركة العقار والعقد والضرائب.
- عدم وجود عقد متداخل على نفس العقار.
- استكمال منتجات التأمين أو الصيانة أو العمولة عند تفعيلها.

## 6. تفعيل العقد

في حالة **Draft**:

1. اضغط **Activate Contract**.
2. اختر:
   - **Automatic Installments**: إنشاء الفواتير المستحقة تلقائيًا.
   - **Manual Installments**: إنشاء جدول الأقساط مع إصدار الفاتورة يدويًا لكل قسط.
3. ينفذ النظام التحقق الكامل.
4. يتحول العقد إلى **Active / Running**.
5. يصبح العقار:
   - **Reserved** إذا كان تاريخ البداية في المستقبل.
   - **Rented** إذا كان العقد يغطي تاريخ اليوم.
6. ينشأ جدول الأقساط مرة واحدة.
7. تنشأ سجلات العمولة مرة واحدة عند وجود وسيط.
8. ترسل رسالة التفعيل عند وجود بريد صحيح.
9. يسجل الحدث في Chatter.

الضغط المتكرر على التفعيل لا ينشئ جدولًا أو فواتير أو عمولات مكررة.

## 7. أزرار العقد حسب الحالة

### Draft

- **Activate Contract**
- **Cancel Contract** — للمدير فقط

### Running

- **Create Invoice**
- **Register Payment**
- **Renew Contract**
- **Close Contract** — للمدير فقط
- **Cancel Contract** — للمدير فقط
- **Send Contract**
- **Create Maintenance Request**

### Expired

- **Renew Contract**
- **Close Contract** — للمدير فقط

### Closed أو Cancelled

لا يمكن إنشاء فواتير إيجار جديدة. تظل البيانات التالية متاحة للعرض:

- الأقساط القديمة.
- الفواتير المحاسبية.
- المستندات.
- الصيانة السابقة.
- Chatter.
- العقد السابق والجديد.
- العمولات.

## 8. الفوترة

### Monthly

ينشأ قسط لكل شهر، ويحسب آخر شهر جزئيًا عند الحاجة.

### Quarterly

ينشأ قسط لكل ثلاثة أشهر. الخدمات الشهرية داخل الربع تحسب بعدد الأشهر مرة واحدة دون مضاعفة السعر والكمية مرتين.

### Yearly

ينشأ قسط سنوي صحيح، مع دعم الفترة الأخيرة الجزئية.

### Full Payment

تنشأ فترة واحدة تغطي مدة العقد كاملة.

### Automatic Installments

يقوم الـCron بإنشاء كل فاتورة أصبح تاريخ استحقاقها أقل من أو يساوي اليوم:

```text
due_date <= today
```

إذا توقف الـCron عدة أيام، يعالج الفترات الفائتة عند عودته.

### Manual Installments

ينشأ جدول الأقساط كاملًا، ويضغط المستخدم **Create Invoice** أمام القسط المطلوب.

### منع التكرار

كل فترة معرفة بواسطة:

- Contract.
- Period Start.
- Period End.
- Invoice Type.

ولا يسمح النظام بأكثر من فاتورة محاسبية لنفس سجل الفترة.

## 9. التأمين والخدمات والصيانة

### Security Deposit

- يحتاج إلى Deposit Product.
- يضاف وفق إعداد العقد.
- لا يتكرر داخل الفترات اللاحقة.

### Extra Services

- خدمة ثابتة: مرة واحدة.
- خدمة شهرية: حسب عدد الأشهر التي تغطيها الفترة.
- تستخدم منتج وضريبة الخدمة نفسها.

### Maintenance

- الصيانة المضمنة في الإيجار لا تنشئ بندًا منفصلًا.
- الصيانة المدفوعة منفصلًا تستخدم Maintenance Product.
- يمكن إنشاء طلب صيانة من العقد الجاري أو من Portal.

## 10. التجديد

1. افتح عقدًا جاريًا أو منتهيًا أو مغلقًا.
2. اضغط **Renew Contract**.
3. تاريخ البداية الافتراضي:

```text
Old Contract End Date + 1 Day
```

4. راجع الإيجار والمدة والإعدادات.
5. ينشأ عقد جديد كمسودة ويرتبط بالعقد السابق.
6. لا يغلق العقد القديم تلقائيًا قبل نجاح إنشاء الجديد.
7. عند تفعيل التجديد المستقبلي يظل العقار **Rented** إذا كان العقد القديم ما زال جاريًا، ثم ينتقل تلقائيًا إلى العقد الجديد.

## 11. الإغلاق

الإغلاق متاح لـ **Rental Manager** فقط.

- لا يحذف الفواتير أو الأقساط.
- يسمح بوجود فواتير مستحقة ويذكرها في Chatter.
- يسجل المستخدم والتاريخ.
- يكمل الأنشطة المفتوحة.
- يعيد حساب حالة العقار.

## 12. الإلغاء

الإلغاء متاح لـ **Rental Manager** فقط.

- يجب إدخال سبب الإلغاء.
- لا يسمح بالإلغاء عند وجود فواتير Posted قبل تنفيذ Credit Notes أو معالجة محاسبية واضحة.
- لا يحذف القيود المحاسبية.
- يسجل السبب والمستخدم والتاريخ.
- يعيد حساب حالة العقار.

## 13. الصلاحيات

### Rental Officer

- إنشاء وتعديل العقارات والعقود داخل شركته.
- تفعيل عقد المسودة.
- إنشاء الأقساط والفواتير وطلبات الصيانة وفق الصلاحيات.
- عرض الفواتير المرتبطة.
- لا يمكنه حذف عقد نشط.
- لا يمكنه إغلاق أو إلغاء العقد.
- لا يدير الإعدادات الحساسة.

### Rental Manager

- جميع صلاحيات Officer.
- إغلاق وإلغاء العقود.
- إدارة الإعدادات والقوالب والتقارير والعمولات.
- الوصول فقط إلى الشركات المسموح بها.

## 14. Portal

يظهر للعميل:

- My Rental Contracts.
- Active Contracts.
- Rent Invoices.
- Maintenance Requests.
- Contracts Expiring Soon.

لا يمكن لمستخدم Portal:

- فتح عقد عميل آخر بتغيير الرقم في الرابط.
- فتح طلب صيانة لعميل آخر.
- إنشاء صيانة على عقد لا يخصه.
- إنشاء صيانة على عقد غير ساري.
- الاطلاع على مستندات أو عقارات غير مرتبطة بعقوده.

## 15. المتابعة اليومية المقترحة

1. راجع **Contracts Expiring Soon**.
2. راجع **Overdue Invoices**.
3. راجع **Maintenance Requests**.
4. راجع العقود المحجوزة التي ستبدأ قريبًا.
5. راجع تحذيرات Migration بعد أول Upgrade.
